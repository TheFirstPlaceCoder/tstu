## 📌 О проекте

**MathTool** решает уравнения вида:

```text
A*x² + B*x + C = 0
```

Проект был создан в рамках университетского задания, где предполагалось познакомиться с такими передовыми концепциями программирования, как:

- `if`
- `else`
- переменные
- ввод с клавиатуры
- и, по неподтверждённым данным, функции

К сожалению, в процессе разработки что-то пошло не так.

Вместо одного `main` на 150 строк появились:

- отдельная предметная модель;
- CLI-парсер;
- валидация;
- solver;
- отдельное представление результата;
- отдельный вывод;
- нормальное разделение ответственности.

То есть обычная лабораторная случайно получила архитектуру.

## ✨ Возможности

MathTool умеет:

- ✅ решать квадратные уравнения;
- ✅ решать линейные уравнения при `A = 0`;
- ✅ определять отсутствие действительных корней;
- ✅ принимать коэффициенты интерактивно;
- ✅ принимать коэффициенты через CLI;
- ✅ проверять входные данные;
- ✅ проверять допустимый диапазон коэффициентов;
- ✅ нормально обрабатывать ошибки;
- ✅ не хранить всю программу в одном методе `main`;
- ✅ не использовать переменные вроде `a1`, `a2`, `a_final`, `a_final_final2`.

Последний пункт потребовал особенно серьёзной инженерной подготовки.

## 🚀 Запуск

### Справка

```bash
java -jar mathtool.jar
```

или:

```bash
java -jar mathtool.jar --help
```

---

### Интерактивный режим

```bash
java -jar mathtool.jar solve
```

После чего программа задаст вопросы:

```text
Введите A:
Введите B:
Введите C:
```

Да, здесь всё ещё используется консольный ввод.

**Spring Boot для этого задания подключён не был.**

Пока.

---

### Передача коэффициентов через аргументы

```bash
java -jar mathtool.jar solve -a 1 -b -3 -c 2
```

Результат:

```text
Уравнение квадратное
Дискриминант: 1.000
x1 = 2.000
x2 = 1.000
```

Параметры можно передавать в любом порядке:

```bash
java -jar mathtool.jar solve -c 2 -a 1 -b -3
```

Потому что пользователь почему-то не обязан помнить индекс каждого элемента в `String[] args`.

### `Main`

Точка входа.

Её задача — запустить приложение.

И всё.

Да, `main()` действительно может не содержать всю бизнес-логику проекта.

---

### `CommandLineParser`

Разбирает:

```bash
solve -a 1 -b -3 -c 2
```

Также понимает:

```bash
solve -c 2 -a 1 -b -3
```

Потому что CLI-параметры — это параметры, а не священный ритуал с фиксированными индексами массива.

---

### `Equation`

Представляет уравнение и хранит:

```text
A
B
C
```

Также контролирует корректность коэффициентов.

Таким образом объект:

```text
A = 999999999
```

не путешествует по приложению в надежде, что кто-нибудь когда-нибудь его проверит.

---

### `EquationSolver`

Содержит только математическую логику.

Он не знает:

- что такое консоль;
- что такое `System.out`;
- что пользователь передал через CLI;
- кто вообще решил запускать этот проект в 3 часа ночи перед дедлайном.

Он просто решает уравнение.

Как и положено нормальному сервису.

---

### `EquationSolution`

Результат решения представлен отдельными типами:

```text
LinearSolution
TwoRootsSolution
SingleRootSolution
NoRealRootsSolution
```

Вместо архитектурного шедевра:

```java
double x1 = 0;
double x2 = 0;

boolean hasX1 = true;
boolean hasX2 = false;
boolean maybeRoot = true;
boolean rootExistsProbably = false;
```

---

### `SolutionPrinter`

Отвечает только за вывод.

Потому что:

```java
double d = b * b - 4 * a * c;
```

и:

```java
System.out.println(...)
```

— всё-таки разные обязанности.

## 🛡️ Валидация

Коэффициенты должны быть целыми числами в диапазоне:

```text
[-100000000; 1000000000]
```

### Некорректный тип

```bash
java -jar mathtool.jar solve -a abc -b 2 -c 3
```

Получим:

```text
ОШИБКА: коэффициент A не является целым числом
```

### Выход за диапазон

```bash
java -jar mathtool.jar solve -a 100000001 -b 2 -c 3
```

Получим:

```text
ОШИБКА: коэффициент A находится вне допустимого диапазона [-100000000; 100000000]
```

Программа намеренно не использует проверенный временем подход:

> **«Ну пользователь же нормально введёт.»**

## 🤔 Почему здесь столько классов?

Потому что код иногда имеет неприятное свойство **расти**.

Сегодня:

```text
ax² + bx + c = 0
```

Завтра преподаватель скажет:

> А теперь добавьте кубические уравнения.

Послезавтра:

> А теперь комплексные корни.

Через неделю:

> А теперь GUI.

А потом:

> А почему у вас всё в `main`?

И вот уже один метод превращается в археологический объект, изменение которого требует разрешения Министерства культуры.

Здесь математическая логика отделена от интерфейса, поэтому её можно переиспользовать хоть в:

- CLI;
- REST API;
- Telegram-боте;
- JavaFX;
- Android;
- микросервисе;
- распределённой системе для решения квадратных уравнений;
- Kubernetes-кластере из 17 нод.

Последний вариант особенно рекомендуется для **лабораторной №2**.
